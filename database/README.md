# Writing the PostgreSQL schema yourself

The SQL must follow the normalized model you derived from the current exam
variant. Do not begin with table names from an old theme.

## Translate each normalized sheet into a table

Use this checklist:

| Spreadsheet meaning | PostgreSQL choice |
| --- | --- |
| Surrogate ID | `integer GENERATED BY DEFAULT AS IDENTITY` |
| Required short or long text | `text NOT NULL` |
| Stable source code with leading zeros | `text` plus `UNIQUE` if required |
| Whole quantity | `integer` with an appropriate `CHECK` |
| Money | `numeric(12,2)` or suitable precision |
| Fractional size weight or hours | `numeric(p,s)` |
| Calendar date | `date` |
| Date and time | `timestamp` |
| Yes or no | `boolean` |
| Parent reference | Same type as the parent key plus `REFERENCES` |

Choose precision from the source values and business rules. Do not use
floating-point types for money.

## Creation order

Create tables in the same dependency order used by the CSV workflow:

1. independent dictionaries;
2. master entities;
3. document headers or events;
4. variants, links, and detail rows.

Parent tables must exist before a foreign key can reference them.

## Generic DDL patterns

These are syntax patterns, not a completed exam schema.

### Independent entity

```sql
CREATE TABLE parent_entity (
    parent_id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    source_code text UNIQUE,
    name text NOT NULL
);
```

### Child entity

```sql
CREATE TABLE child_entity (
    child_id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    parent_id integer NOT NULL,
    name text NOT NULL,
    CONSTRAINT child_parent_fk
        FOREIGN KEY (parent_id)
        REFERENCES parent_entity(parent_id),
    CONSTRAINT child_parent_name_uq
        UNIQUE (parent_id, name)
);
```

### Document header and line

```sql
CREATE TABLE document_header (
    document_id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    document_date date NOT NULL,
    party_id integer NOT NULL REFERENCES party(party_id),
    status_id integer NOT NULL REFERENCES status(status_id)
);

CREATE TABLE document_line (
    document_id integer NOT NULL
        REFERENCES document_header(document_id)
        ON DELETE CASCADE,
    item_id integer NOT NULL REFERENCES item(item_id),
    quantity integer NOT NULL CHECK (quantity > 0),
    price_at_event numeric(12,2) NOT NULL CHECK (price_at_event >= 0),
    PRIMARY KEY (document_id, item_id)
);
```

If the same item may legally appear more than once in one document, use a line
ID or line number instead of assuming `(document_id, item_id)` is unique.

### Many to many link

```sql
CREATE TABLE entity_a_entity_b (
    entity_a_id integer NOT NULL REFERENCES entity_a(entity_a_id),
    entity_b_id integer NOT NULL REFERENCES entity_b(entity_b_id),
    relationship_date date,
    PRIMARY KEY (entity_a_id, entity_b_id)
);
```

## Constraints to consider

For every table ask whether it needs:

- `PRIMARY KEY`;
- `NOT NULL`;
- `UNIQUE` for a natural key;
- `FOREIGN KEY`;
- `CHECK (quantity >= 0)` or another domain boundary;
- `ON DELETE CASCADE`, `RESTRICT`, or no special delete action.

Do not add a constraint only because it appeared in an old theme. Derive it
from the current business rules.

## CSV preparation

Each CSV should contain:

- exactly one table;
- database column names in the first row;
- no formulas, titles, totals, notes, merged cells, or blank separator rows;
- explicit IDs and foreign-key IDs created during normalization;
- consistent UTF-8 encoding and delimiter;
- values compatible with the chosen PostgreSQL types.

When importing explicit IDs, `GENERATED BY DEFAULT AS IDENTITY` permits the CSV
value while still generating IDs for records later created by the application.

## pgAdmin import sequence

For each table:

1. Right-click the table and choose Import/Export Data.
2. Select Import and the correct CSV file.
3. Set UTF8, Header, the exact delimiter, and `"` as the quote character.
4. Select columns in the same order as the CSV when required.
5. Import all parents before their children.
6. Stop on the first error and fix its cause instead of disabling constraints.

After importing explicit identity IDs, synchronize the sequence:

```sql
SELECT setval(
    pg_get_serial_sequence('public.parent_entity', 'parent_id'),
    COALESCE((SELECT MAX(parent_id) FROM parent_entity), 1),
    EXISTS (SELECT 1 FROM parent_entity)
);
```

Repeat it for each identity column imported from CSV.

## SQL validation

### Row counts

```sql
SELECT COUNT(*) FROM parent_entity;
SELECT COUNT(*) FROM child_entity;
```

Compare them with the workbook `CHECKS` sheet.

### Duplicate natural keys

```sql
SELECT source_code, COUNT(*)
FROM parent_entity
GROUP BY source_code
HAVING COUNT(*) > 1;
```

### Orphan rows

```sql
SELECT c.*
FROM child_entity c
LEFT JOIN parent_entity p ON p.parent_id = c.parent_id
WHERE p.parent_id IS NULL;
```

The expected result is zero rows.

### Reconcile totals

```sql
SELECT SUM(quantity) FROM document_line;
SELECT SUM(quantity * price_at_event) FROM document_line;
```

Compare these values with the raw source and normalized workbook.

### Check identity generation

Insert one temporary test row inside a transaction and roll it back:

```sql
BEGIN;

INSERT INTO parent_entity(name)
VALUES ('identity test')
RETURNING parent_id;

ROLLBACK;
```

The generated ID must be greater than the imported maximum.

## What not to do

- Do not import a wide raw sheet into one final table.
- Do not remove foreign keys to make a broken import succeed.
- Do not store several IDs or names in one text cell.
- Do not use names as foreign keys when stable integer IDs were created.
- Do not create an ID in PostgreSQL that differs from the IDs already used by
  child CSV files.
- Do not add application code until the database checks pass.
